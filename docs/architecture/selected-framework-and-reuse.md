# 已确定的技术框架与复用方案

更新时间：2026-10-14

## 1. 最终技术决策

### 小程序端：原生微信小程序

- 技术：JavaScript ES6+、WXML、WXSS、原生 `Page/Component`、微信原生媒体与网络 API。
- 基线：保留 `D:\project\learn`，不以外部仓库替换现有课程入口。
- 明确不采用：Taro、Uni-app、TypeScript、Skyline 作为第一版主渲染框架。
- 原因：当前项目已有可运行页面；业务资产集中在课程、词典和学习流程，而不是跨端 UI；原生方案包体小、迁移风险低、便于接入现有 API。

### 服务端：适配层优先

小程序 → 统一业务适配层 → `ruflo`/既有 7500km API/`ruflo_content`。客户端不直接暴露旧系统签名、密钥、生产数据库或支付参数。CloudBase 仅保留为未来低运维实验方案，不作为当前主链路。

### 内容与学习逻辑：服务端数据、本地纯逻辑

课程、词典、题库和媒体引用由服务端提供；题目生成、复习调度、排序、错题记录等可测试逻辑放在小程序端纯 JS 模块，同时由服务端保存最终学习结果。

## 2. 两个新仓库的复用边界

| 来源 | 可复用内容 | 复用方式 | 不复用内容 |
|---|---|---|---|
| `lingosnake-main/src/core` | `scheduler`、`quiz`、`word-order`、`word-forms`、`session-lock`、导出逻辑 | 逐模块改造成俄语字段适配后的 `services/learning/` | 英语数据、视觉主题、整套页面、仅本地存储的用户模型 |
| `lingosnake-main/tests` | 调度、题目、词形、会话锁和导入导出测试结构 | 迁入 Node.js 纯逻辑测试，加入俄语样例 | 直接沿用英文断言和字段 |
| `lingosnake-main/src/utils/material.js` | 多教材隔离、激活教材、进度按教材分开 | 改为 `book_id`/课程版本维度 | 将完整教材词库打进小程序包 |
| 官方示例 `components` | `popup`、导航栏、空状态、可复用组件注册方式 | 按需复制并改为本项目样式 | 不复制整个示例工程和页面树 |
| 官方示例登录/支付 | `wx.login`、`wx.requestPayment` 调用顺序和异常处理示例 | 仅作为客户端边界参考 | 不采用其演示云函数、测试金额或“支付成功即授予权益”逻辑 |
| 官方隐私/协议页面 | 隐私授权、用户协议和页面组织 | 上线前按真实主体信息重写 | 不复制示例文案 |

两个仓库均为 MIT 许可，但复用代码时仍需保留许可证记录，并对业务代码做独立改造。

## 3. 建议的目标目录

```text
learn/
├─ pages/                         # 课程、词典、学习、题库、我的
├─ components/                    # 课程卡片、词条卡片、答题选项、空状态
├─ services/
│  ├─ api/                        # request、认证、错误和接口适配
│  ├─ content/                    # 课程/词典/题库数据转换
│  └─ learning/                   # scheduler、quiz、word-forms、session-lock
├─ data/content_samples/          # 脱敏开发样本，不放用户数据
├─ tests/                         # 纯 JS 逻辑测试
└─ docs/architecture/             # 路线、字段、复用和验收文档
```

页面只负责状态展示和交互；`services/content` 把远端字段转换为统一模型；`services/learning` 不依赖 `wx`，保证可由 Node.js 单独测试。

## 4. 俄语领域适配规则

LingoSnake 的 `word`、`phonetic`、`meanings`、`wordForms` 不能直接对应当前数据。统一适配为：`word`、`accent`、`wordClass`、`meanings`、`forms`、`examples`、`audioUrl`、`bookId`、`sourceId`。俄语词形优先使用 `e_change_word` 的原型—变形关系，教材词汇作为学习范围，主词典和例句作为详情增强。

复习调度首版可以沿用 1/2/4/7/15/30 天间隔，但必须记录服务端事件：学习开始、答题、判定、复习计划变更和完成时间，不能只保存客户端 JSON。

## 5. 开发顺序

### Sprint 1：基线收敛

清理重复视频页面，统一请求错误处理，关闭默认本地样本回退；完成课程—章节—试听媒体的真实映射和真机验收。

### Sprint 2：学习核心

迁移并改造调度、题型、词形和错题逻辑；先用教材 `id=1` 和 `id=13` 做真实俄语数据测试，完成每日任务和断点续学。

### Sprint 3：词典与词汇

接入查词、重音、词性、变形、例句、音频、收藏和教材词表；增加搜索防抖、分页和空状态。

### Sprint 4：题库闭环

接入试卷、题型、题目、原文、音频和解析，支持专项练习、错题重做和成绩记录。

### Sprint 5：登录与商业化

完成微信登录、用户协议、权益查询、订单状态机、支付回调幂等、退款和人工对账后，才开放真实购买。

### Sprint 6：AI 增值

先做基于已审核内容的错题解释、复习建议和学习报告；发音评测接入 `Russion_Stt` 独立服务，不阻塞主产品发布。

## 6. 质量门槛

- 纯逻辑模块必须有 Node.js 自动化测试；每个复习规则、题型和字段适配都要有俄语样例。
- 每个页面须通过开发者工具、真机、弱网、空数据、过期登录和媒体失败场景。
- 生产凭据、用户身份数据和完整私有教材不得进入小程序静态包、Git 或 AI 提示词。
- 发布前必须验证小程序合法域名、隐私协议、媒体权限、支付回调和权益校验。

## 7. 第一批实际产出

1. 新建 `services/learning/` 与俄语字段适配器。
2. 将首个课程切片改为真实内容映射，保留本地样本为显式测试开关。
3. 迁移 LingoSnake 调度和题型测试，补充俄语数据夹具。
4. 编写内容规范层字段映射报告，再决定服务端接口的最小集合。
