# 媒体地址与账号凭据边界

## 客户端规则

视频页将课程适配层返回的媒体URL原样交给播放器，不读取账号token来构造媒体地址。初始化、切换和下一节均不得追加账号凭据；现有签名、查询参数与fragment不改写，也不修改传入的video对象。

这是去除危险隐式行为，不是新建鉴权系统。当前仅本地测试视频经过播放确认，不能由此宣称远程付费媒体可用。

## 服务端接入要求

- 公开试听使用公开媒体URL；受保护内容使用服务端校验权益后签发的、短期且限定资源的媒体票据URL。
- 不把账号访问token当媒体票据，不依赖前端hasPurchased放行；票据失效需要可恢复的重新获取流程。
- 发行前另行验证合法HTTPS域名、媒体重定向、票据有效期/撤销、未购买/退款访问和日志脱敏。小程序能力与支付政策按接入时官方规则核验。
- 既有后端若只支持将账号token拼到视频URL，须在服务端适配媒体授权；不得以恢复客户端无条件拼接作为兼容方案。

进度上报仍通过`utils/request.js`，受`enableRemoteWrites`和登录条件保护。移除媒体token拼接不改变这些写保护，也不为本地演示启用登录或交易。

## 验证边界

`scripts/test_video_media_credentials.js`执行真实Page逻辑，使用虚构账号凭据检查初始化/切换/下一节、带query/签名/fragment与外域场景。配合访问策略、响应校验和写保护回归。该测试不请求外部服务器，不证明票据服务、重定向安全或实机媒体鉴权已经部署。
