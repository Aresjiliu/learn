# 俄语 7500 业务价值与开发计划书

> 版本：v1.0｜日期：2026-10-14｜范围：微信小程序及其内容、学习、题库和 AI 扩展能力

## 1. 结论与目标

当前最有价值的资产不是某个客户端，而是已经积累的俄语内容、课程结构、考试题库、词形关系和多年业务流程。建议将“俄语7500”从单一课程 App 拆为“内容入口 + 学习工具 + 备考产品 + AI 增值服务”四条产品线，以小程序降低获客和使用门槛，以低价订阅、课程包和 AI 服务恢复收入。

第一阶段目标不是重写全部系统，而是用现有内容完成一个可上线验证的学习闭环：课程试听/购买 → 词汇学习 → 练习 → 错题复习 → 学习反馈。

## 3. 产品拆分与优先级

### P0：小程序内容入口

课程列表、课程详情、免费首节、章节目录、关联词汇、收藏和学习进度。首发只依赖公开内容和可访问媒体，暂不绑定支付。

### P1：词典与词汇学习

俄汉查词、重音/词性/变形/例句、教材词表、收藏生词、间隔复习、错词本和每日任务。核心逻辑参考 `Russion1`、`Harmony` 与 LingoSnake 的模块组织方式。

### P1：考试与题库

按等级、考试类型和教材组卷；提供免费试题、专项练习、解析、错题重做和阶段测评。先使用已有结构化题库，不先做复杂 AI 出题。

### P2：商业化

采用低价月卡/季卡、单教材包、考试专项包和连续学习会员。权益必须由服务端校验，支付回调、退款、过期和重复购买完成后再开放正式交易。

### P2：AI 增值

优先做内容增强型 AI：错题解释、学习计划、词汇问答、例句改写和学习报告；其次做发音评测。AI 只能调用已审核词典和课程内容，禁止把用户身份数据直接发送到模型。

## 4. 技术路线

首发采用原生微信小程序，保留页面与业务服务层分离。`services/` 负责课程、词典、考试和学习记录，页面不直接拼接旧 API。后端采用“适配层优先”：小程序 → 统一服务层 → 既有 API/本地内容库；签名、密钥、权限和支付逻辑全部留在服务端。

数据分三层：

1. `raw_*` 原始层：完整保留远端字段、来源和导入批次。
2. 内容规范层：统一课程、单词、词形、例句、题目、媒体和版本字段。
3. 学习服务层：用户学习进度、生词、错题、计划、订阅和 AI 使用记录。

不将用户数据放入小程序静态包；生产只读账号继续只读，不在开发阶段修改生产库。

## 5. 分阶段实施计划

### 阶段 0：资产与数据基线（当前）

完成数据库快照、字段字典、媒体清单、许可证核查和敏感数据隔离。验收：内容表行数可对账，课程—词汇—词典关联有报告，生产配置不进入代码。

### 阶段 1：首个可验证切片

完成“课程列表 → 详情 → 免费首节 → 关联词汇”，在微信开发者工具和真机验证网络、空状态、错误状态、媒体权限和本地样本开关。随后用真实接口覆盖率决定直接复用旧 API 或继续适配层。

### 阶段 2：内容服务与词典

建设内容规范视图和版本化查询；新增词典搜索、词形归一、重音、例句、教材词表和收藏。验收重点是搜索速度、俄语编码、字段完整性和数据来源可追溯。

### 阶段 3：学习闭环

实现每日任务、学习会话、SM-2/间隔复习、错题本、学习统计和断点续学。先复用 `ruflo` 已有学习表和逻辑，避免重新发明相互冲突的进度模型。

### 阶段 4：题库与轻量商业化

接入试卷、题型、原文、音频和解析；先上线免费试卷与权益校验，再接微信支付、订阅、退款和运营后台。支付上线前必须完成回调幂等、订单状态机和人工对账。

### 阶段 5：AI 增强与增长

基于用户学习记录生成复习建议、错题解释和学习报告；独立接入发音评测。通过分享卡片、连续学习激励、课程试学和考试报告形成自然增长，不以大模型替代已审核教材内容。

## 6. 关键指标与验收门槛

- 内容：课程、词汇、题目、例句和媒体引用可追溯，导入前后行数可对账。
- 产品：首屏可打开，核心页面无阻塞错误，免费首节可真实播放，学习进度可恢复。
- 业务：记录课程详情到试听、试听到注册、注册到学习、学习到付费的漏斗；按产品线分别统计留存和转化。
- 安全：生产凭据不入库，用户隐私脱敏，支付和 AI 请求不携带不必要的身份信息。
- 发布：必须通过开发者工具、真机、弱网、无网络、过期登录和空数据场景验证。

## 7. 主要风险与决策门

旧 API 字段、登录、媒体地址和小程序域名可能不兼容；先用首个切片验证，不在未验证前迁移全部业务。课程封面和视频资产不完整时，优先使用可授权的试听素材。支付和 AI 属于高风险模块，分别在内容闭环稳定、权限模型稳定后实施。外部仓库仅借鉴模块和测试组织，优先使用 MIT/Apache-2.0 项目并保留许可证，不整仓替换现有业务。
