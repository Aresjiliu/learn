# 词典体验重建设计

状态：用户已确认按白底、紧凑搜索、黑色正文、少量珊瑚红及微信原生白色导航方向实施；替代被否定的第一轮“卡片补样式”。新综合 goal 已启用。当前文档不声称 UI 已实现。

## 目标与路线

推荐“Russion1 信息架构 + Vant 原生基础组件 + 自有俄语业务组件”。不更换原生 JS，不搬 HarmonyOS 平台 API，不在此轮重做课程、题库和支付。

比较三条路线：继续手写基础组件可少依赖但重复投入和视觉漂移明显；完整复制 Russion1 需重写 ArkUI/存储/网络且会带入旧缺陷；推荐路线复用基础交互与已核验业务，成本受控。采用前必须检查正式发布物、许可、依赖和包体。

## 视觉规范

- 以 `Russion1/ui` 为方向，不追求逐像素搬广告和系统状态栏。词典页面单独配置白底黑字的微信原生导航，保留返回与胶囊区域，不自画刘海。
- 画布白色、浅灰分区；文字 `#202124`，辅助 `#737780`，分割线 `#eef0f3`；建议强调色 `#ef5b56`。如用户选择蓝色品牌，仅替换语义强调色，不改变布局。
- 统一系统无衬线：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`；在微信真实渲染核对中文、俄文及组合重音。词典局部生效，避免无审查地改变所有页面。
- 页面边距 32rpx，搜索高 88rpx；词头 52rpx/1.3，正文 30rpx/1.65，辅助 24rpx/1.5。行式结果不加大阴影；可点图标的外层命中区至少 88rpx。
- 长俄文不截断词头，窄屏可换行；组合重音不拆散。正文随内容自然增长，不固定卡片高度。

## 三个页面状态

### 搜索首页

紧凑搜索 → 最近查词（最多 20 条，可单删/清空）→ 示例查询（明确不是实时热榜）→ 已可使用的学习工具。未接入的拍照、语音、会员和广告不显示；生词本须可用后才显示入口与真实数量。

输入框支持键盘搜索、显式提交与清空。首片不做逐键网络联想；俄语字母辅助输入作为独立增量，不承诺能由小程序切换 iOS 系统俄语键盘。

### 搜索结果

同一搜索框 → 结果数量/来源状态 → 行式结果（词头、词性、两行摘要、匹配类型）→ 分页状态。沿用服务端排序，不将释义命中/词形候选冒充精确词头；多原型保留候选和歧义提示。

新搜索立即撤下上一查询结果或明确显示正在查询，不将旧列表标成新词结果；分页失败保留当前列表，提供局部重试。切词/清空/离开页面使旧响应失效。样本回退与完整词典失败保持诚实提示。

### 词条详情

词头与已核验重音 → 词性与图标发音 → 收藏状态（生词本完成后启用）→ 分区内容。首片仅显示现有可靠释义与例句；结构化批次到位后拆义项、例句、相关形式与变格。

有数据才显示对应分区；无例句、变格、俄俄释义时隐藏该标签，不填生成内容。不为缺少生词本实现预留空收藏按钮。音频只有可信可播放 URL 才显示声音按钮，失败可重试；开发音频标识收敛但不隐藏。切词、后台和卸载停止旧音频。

## 数据与模块边界

- 保留 `services/content-api.js`、稳定 `dict:...` ID、只读快照及音频控制器。
- 新 `services/dictionary-presentation.js`：将原始字段整理为 `headword/wordClass/summary/meaningBlocks/examples/availableSections`；旧平面释义原样保留，不能靠猜编号拆义项。
- 新 `services/dictionary-history.js`：注入 storage 的纯逻辑，key `dictionary_history_v1`，最近优先、最多 20、保留显示词与严格归一化键，保留 ё/й；有响应的明确查询才记录，无结果可记录、网络失败不记录。
- 新 `components/dictionary-entry` 只负责结果呈现和 `open` 事件；发音与词头逻辑按需要独立组件，禁止再手画整套通用基础组件。
- 结构化详情独立设计：先检查导出字段覆盖和类型，保留 `XJSY` 义项/例句、可信重音等，版本化构建新批次并重新核对音频绑定，不原地修改源库。
- 本地生词本下一片使用稳定 ID、快照摘要、来源、时间与复习状态；本地写入不属于远程写入，`enableRemoteWrites=false` 保持。存储成功才显示已加入。

## 错误与隐私

历史损坏按有效记录恢复，单条异常不崩页；写满/读写失败展示非阻塞提示，不伪称已保存。清空历史需确认。历史不上传、不写调试日志。未知字段渲染为文本，不注入外部 HTML/脚本。缓存、组件字体等网络依赖需要明确审查。

## 验收门禁

1. 自动行为：组件事件值、分页、清空、连续换词、旧响应、发音生命周期、历史去重/容量/损坏/删清、俄语 ё/й 和重音。
2. 真实截图：390×844（iPhone12/13 Pro档）、375×812 与 320×568；记录模拟器/真机区别、系统字体/字号、基础库与内容版本。至少覆盖空首页、历史、精确/释义/词形结果、长词、详情、无音频、播放失败、加载、无结果、服务失败。
3. 三项硬条件：正文和按钮不出屏；标题/按钮不重叠且滚动内容不被安全区遮挡；第一屏能看见主操作和实际学习内容。与用户基准并排评审，不能用正则或网页近似图替代小程序截图。
4. 组件字体断网与冷启动检查，微信编译无缺组件/字体错误；包体排除 ui/、源数据和依赖源码，实际新增字节记录；超预算先减组件而不是盲目升级框架。
5. 完整回归和独立审查通过后才能提交交付；支付、HTTPS、真机等未验收不得勾选生产完成。
