# 词典发音资源审计设计

## 目标与选择

延续 A3，先确定本机 1,122 个教材音频文件能够覆盖哪些主词典词条，再接入可靠发音。直接按旧音频哈希关联无法覆盖教材来源；模糊拼写或宽松 `ё→е` 关联有误读风险。因此选择严格原词候选审计，不新增下载或生产连接。

## 输入、输出和边界

读取自有教材 gzip 导出、只读 v4 词典索引和显式缓存目录。沿用词典严格规范化：忽略大小写与重音，保留 `ё` 和 `й`。只有十进制教材 ID、32 位十六进制文件名、目录内普通文件、大小受限且通过既有 MP3 结构检查的文件可形成候选。必须核对同一原词的所有合法来源音频哈希；即使其中只有一个已缓存，也不能掩盖多音频歧义。

按稳定 `dict:` ID 输出候选、教材来源 ID、文件 SHA-256 和检查层级；单独统计无本机文件、文件损坏、多哈希歧义及主词典原始哈希覆盖。完整候选报告仅写入 Git 忽略的 `data/generated/`，公开文档只记录统计与复跑命令。拒绝输出覆盖输入导出、索引或缓存文件。

这次审计不修改 SQLite、原始导出、MP3、页面或运行时音频索引，不自动发布候选。结构检查不是解码或语义听审；同形异音、去重音后的词条与教材发音需要后续确认，不能宣称新增可播放覆盖。

审计仅接受独立 rollback-journal 格式的已发布 SQLite 快照；文件头为 WAL 或存在 `-wal/-shm/-journal` 均拒绝，且不通过 SQLite 打开源文件。输入先哈希、复制到忽略目录中的临时私有快照并核对复制哈希；查询只在无 WAL 的私有副本上使用 `immutable=1`，结束再次核对原始输入。变化即拒绝报告。该策略约需与索引同等大小的临时磁盘空间；失败也清理私有副本，不忽略真实 WAL 数据。

## 验证

临时夹具覆盖重音、`ё/е`、`й/и`、重复词条 ID、缺失/损坏文件、路径穿越、单缓存多来源哈希歧义、来源追溯与输出保护。运行真实资产审计，核对输入未变；然后补充独立审查与阶段门禁。下一切片再设计核验清单到只读服务的接入。
