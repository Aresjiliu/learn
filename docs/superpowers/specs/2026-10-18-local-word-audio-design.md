# 教材词汇本地音频接入设计

## 依据与目标

本地 `n_study_book_word` 导出中，`change_form_sound` 有 61,325 条非空值；《东方教材大学俄语3》的 1,247 个词中有 1,122 条。抽样哈希文件在原 App 媒体服务返回 `206` 和 `audio/mpeg`。当前小程序导出样本丢掉了该字段，因此课程词汇页无法播放这些现有发音。目标是在本地联调中让有实物的教材词发声，并维持题库音频的独立缺失状态。

## 方案选择

- 直接让小程序访问旧媒体服务：改动少，但服务只有 HTTP，不适合发布与真机合法域名验收。
- 使用公共 TTS：不依赖旧文件，但发音、稳定性和使用条件尚未验证。
- **选用本地缓存：**按词条 ID 从只读导出取 32 位音频哈希，下载现有 MP3 到 Git 忽略的 `audio/wordaudio/`，由本地媒体服务以 `/wordaudio/<哈希>.mp3` 提供。小程序消费相对音频路径；以后可由 HTTPS 媒体域名替换基址。

## 数据与边界

生成器仅接受十进制词条 ID 与 32 位十六进制哈希，产出紧凑的 `id -> 文件名` 运行时索引；不把原始数据库、完整 MP3 或旧 HTTP 服务地址提交到 Git。下载器需限制文件大小、验证音频响应、跳过已验证文件并记录失败项。实际缓存可用的文件才进入播放索引，避免页面展示失效按钮。

词典详情和教材词汇展示使用独立的本地词音频开关；题库 `enableLocalTestAudio` 继续保持关闭，直到题目与原文音频完成逐条匹配。播放器沿用 `services/media/audio.js`。本地 HTTP 仅用于开发者工具调试；发布需要 HTTPS 域名和真机验收。

## 验收

至少一条教材词在小程序词典详情页完成点击、播放、结束与失败提示；本地媒体服务的 HEAD/Range 返回长度与实际字节一致。批量缓存后校验索引中的每个文件都存在；阶段检查、包体检查和页面回归通过。GUI 编译与真机表现单独记录。
