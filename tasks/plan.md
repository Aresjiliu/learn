# 生产化执行计划

## 目标与边界

把原生微信小程序从本地演示推进到可验收的俄语学习产品。保留现有课程、词典、题库适配层和只读内容资产；不把原始导出、媒体或个人信息提交到 Git。未完成商户资质、支付回调和权益校验前，`enableRemoteWrites=false`，购买入口保持关闭。

## 架构与依赖

先建立可部署的内容查询与媒体来源，再让词典页面、生词本和复习使用同一个稳定词条 ID。学习事件与个人身份分离；跨设备同步必须晚于登录及冲突规则。交易按“商品/价格 → 订单 → 微信预支付 → 回调与查单 → 权益 → 服务端媒体授权”顺序实施；不能从小程序支付回调直接发放权益。本地 `scripts/serve_content_api.py` 仅是原型，不承载生产支付。

## 里程碑

1. **词典可用**：全量俄中检索、词形归原、来源清楚；服务故障与样本回退不混淆；真实音频有可核验文件。
2. **学习闭环**：词典详情、生词本、到期复习、课程词和错题互通；未审核题目继续拦截。
3. **视觉可验收**：统一组件和状态；在 320–430px、iPhone/Android、弱网下有截图与操作记录。
4. **交易可验收**：取得必要商户权限后完成订单、支付、退款及权益测试，再启用购买。
5. **发布可运维**：HTTPS、域名、监控、备份、隐私、自动化和回滚演练齐备。

## 共同完成标准

每项先有失败用例或可复现记录，再实现、跑聚焦测试和 `scripts/check_phase1.ps1`；媒体/UI 必须补开发者工具与真机证据。检查 Git 文件清单、许可证和凭据，再提交并核实远端实际收到提交。仅静态测试通过时标注“待人工验收”。

## 风险与待外部确认

- 当前词典依赖本机 HTTP，完整导出约 16.6 万不同词；部署方案和搜索性能需要实测。
- 主词典原始音频字段覆盖有限；先盘点已拥有文件，再选择补录或标识清楚的合成音。
- 商户号、已认证小程序、AppID 绑定、交易类小程序要求和 HTTPS 回调域名是支付前置条件；资质未就绪不阻碍词典与学习开发。
- GitHub 连接近期反复重置；本地提交不等于推送成功，以远端提交哈希为准。

详细任务与依赖见 [todo.md](todo.md)。每个具体功能开工前再写对应的短规格与实现计划，避免跨子系统的大型改动。
